# 진행 기록

"부장님 몰래" 백엔드를 어떤 순서로, 어떤 결정을 거쳐 만들었는지 정리한 문서다. 처음 정리는 2026-11-26 PR #4 머지 직후였고, 마지막 갱신은 2026-11-27 AI2-BE PR #24·AI2-FE PR #17 머지 직후다. 프론트엔드(AI2-FE) 작업도 여기에 함께 적는다.

- 지금의 규칙과 수치는 [GAME_DESIGN.md](../GAME_DESIGN.md)가 기준이다.
- 서버와 주고받는 명령·메시지는 [PROTOCOL.md](../PROTOCOL.md)에 있다.
- 실행과 배포 방법은 [README.md](../README.md)에 있다.

이 문서는 그 결과에 이르기까지의 과정을 담는다.

## 1. 지금 할 수 있는 것

친구 2~4명이 초대 코드로 한 방에 모여 방장이 정한 근무 시간 동안 한 판을 끝까지 하거나, 혼자서 1인 플레이로 명예의 전당에 도전할 수 있다. 회원(이름 + 비밀번호)과 게스트(닉네임만)로 들어오고, 회원의 판 결과는 PostgreSQL에 남는다. 게임 안에서 목소리로 이야기할 수 있다(WebRTC). 따로 만든 프론트엔드(AI2-FE)가 이 기능을 모두 화면으로 보여 준다.

## 2. 진행 순서

### 0단계: 기존 코드 검토 (레포 이전)

이미 동작하던 것을 봇 2명과 브라우저로 한 판 돌려 확인했다.

- **이미 동작하던 것:** 방 만들기·입장·시작, 합계 업무와 수당, 종목 3개 상수곱 풀 매매, 뉴스 21장, 2초 순찰과 방향성 발소리, 주식 창 적발과 10초 훈계, 뉴스 알림창.
- **검토에서 나온 개선점:**
  - 화면의 기준가와 실제 체결가가 달라 헷갈린다.
  - 가격이 뉴스 사이에 거의 멈춰 있다.
  - 도착 뒤 2초 유예가 넉넉하다.
  - 발소리 위치가 구간 끝에서 살짝 튄다.

### 1단계: 첫 커밋 전 작업 (`0b4cdfe`)

레포를 만들기 전에 원래 폴더에서 한 작업으로, 첫 커밋에 함께 들어갔다.

- **주문 전 예상 체결 금액:** 서버와 같은 공식으로 화면에서 계산한다.
- **가격 변동 모델:** 평소 흔들림, 뉴스 반응 다양화(과잉 반응, 소문에 사서 뉴스에 판다), 찌라시(진짜 70%, 가짜 30%), 매매 흔적, 장 마감 변동성을 넣었다. 500판 시뮬레이션으로 수치를 정했다.
- **풀 깊이:** 100주에서 1,000주로 늘렸다. 100주에서는 뉴스를 잘 읽어도 판당 2천 원 남짓밖에 못 벌었다.
- **시세 갱신:** 2초에서 1초로 바꿨다. 모든 비율을 초 단위로 바꿔서 체감은 그대로이고, 순찰은 2초 박자를 유지한다.
- **업무 시간 기록:** 업무 1건마다 전체 시간과 업무 창 기준 시간을 CSV로 남긴다. 업무 수당을 정할 근거로 쓴다.
- **레포 정리:** 폴더를 `office-stock/office-stock-BE`로 옮기고 GitHub 레포(AI2-BE)를 만들었다.

### 7단계: 종목과 뉴스 늘리기 (브랜치 `feature/more-stocks-news`)

- 종목 5개(하늘항공·온누리제약·반짝반도체·든든은행·배달번개)를 출근 전 흐름과 함께 더했다.
- 뉴스를 126장으로 늘렸다. 여러 종목·외부 사건 뉴스 46장에는 전염병 대유행, 금리, 유가, 반도체 부족 같은 실제 사건 모티브가 들어 있다.
- 뉴스 간격을 20초 고정에서 25~40초 무작위로 바꿨다. 플레이테스트에서 뉴스가 너무 잦다는 의견이 있었다.
- 200판 시뮬레이션: 20분 판에 속보 평균 36.5번, 찌라시 22.1번, 한 판 안 반복 0번.
- 이어서 실제 기업 이름을 다른 업종과 섞은 패러디 종목 20개(삼성자동차, 현대전자, 카카오조선, 롯데반도체 등)를 더했다. 일반 종목은 28개, 뉴스는 270장(여러 종목 뉴스 70장)이 됐다. 사드 보복, 일본 수출 규제, 레고랜드, 동학개미, 수에즈 운하, 후쿠시마, 누리호 같은 사건을 모티브로 한 외부 뉴스를 더했고, 기존 외부 뉴스에도 새 종목의 반응을 넣었다.

### 8단계: 판마다 상장 종목 (브랜치 `feature/listed-stocks`)

- 30종목일 때 시세 메시지를 재 보니 매초 15.4KB(그중 호가 10.6KB), 시작 차트 452KB였다. 프론트엔드는 호가·풀을 선택한 종목 것만 쓰고, 봉은 모든 종목을 이어 붙인다.
- 판마다 일반 종목 12개를 무작위로 상장하고(`game.stocks-per-game`), 뉴스 덱과 `catalog` 메시지를 그 판 종목에 맞췄다. 기초 종목이 뽑히면 레버리지 종목도 함께 나온다.
- 결과: 매초 6.5KB, 시작 차트 181KB. 종목 하나가 한 판에 받는 속보는 평균 1.3번 → 4.6번.
- 프로토콜 모양은 그대로라 프론트엔드는 바꿀 것이 없다. 다만 종목 목록을 고정해 두지 말고 매 판 `catalog`로 받아야 한다.

### 9단계: 2차 플레이 피드백 (브랜치 `feature/easier-tasks`)

- 엑셀 집계를 쉽게 했다. 거래처 3~5개·세 자리 금액에서 2~3개·100 단위 금액(예: 700+900)으로 바꿨다. 전자결재는 그대로 둔다(어렵지 않다는 의견).
- 업무 게이지를 남이 아니라 **나에게** 보이게 바꿨다. 내 주식을 보느라 남의 게이지를 볼 틈이 없었다. 동료에 대해서는 훈계 중인지만 보낸다.
- 마이크 소리 크기를 나와 다른 사람 모두 볼 수 있게 했다(`MIC n`, `mic` 메시지, `market.micLevels`). 목소리는 보내지 않고 크기만 보낸다.

### 10단계: 터널 플레이와 콘텐츠 다듬기

- 따로 만든 프론트엔드를 터널 하나로 열 수 있게 했다(`game.allowed-origins`에 trycloudflare 주소, 프론트엔드 `allowedHosts`와 preview 프록시). AI2-BE#10, AI2-FE#1.
- 찌라시 문구를 호재·악재 3개씩에서 25개씩으로 늘렸다.
- 종목마다 업종(`sector`)을 넣어 `catalog`로 보낸다. 외부 뉴스가 어떤 종목에 닿는지 시세표에서 바로 읽게 한다.
- 메일을 16통에서 48통으로 늘리고 사람마다 섞은 순서로 나눠 준다(한 판 안 반복 0번). 결재 품목·기안자, 엑셀 거래처·시트 이름도 늘렸다.

### 11단계: 프로필(DB)과 솔로 게임 (브랜치 `feature/profiles-db`)

- PostgreSQL(Docker compose)과 JPA·Flyway를 붙였다. 진행 중인 게임은 메모리, 끝난 판의 결과와 프로필만 DB에 둔다.
- 프로필: 이름 정하기(비밀 열쇠 방식), 이름 바꾸기, 꾸미기 설정 저장. 방에서 P1, P2 대신 이름으로 부른다.
- 솔로 게임: `SOLO 분`(5·10·15·20분), 메신저·찌라시 없음, 보이지 않는 세력(사 모았다 털기 / 던졌다 되사기).
- 퇴근 정산 때 이름 있는 사람의 결과를 저장하고, 솔로는 근무 시간별 명예의 전당(`LEADERBOARD`)으로 보여 준다.

### 12단계: 회원과 비회원 (브랜치 `feature/members`)

- 비밀 열쇠만으로는 기기를 바꾸면 프로필을 잃고, 같은 이름으로 다시 만들 수도 없었다. 회원(이름 + 비밀번호, 어느 기기에서든 로그인)과 비회원(닉네임만, 저장 없음)으로 나눴다.
- `SIGNUP`, `LOGIN`, `AUTOLOGIN`, `LOGOUT`, `GUEST`, `PROFILE PASSWORD`. 자동 로그인 열쇠는 기기마다 따로(`login_token` 표, V2 마이그레이션). 비밀번호 5번 실패 시 1분 잠금.
- 결과 메시지에 저장 여부(`recorded`)와 안내 문구를 넣고, 비회원에게는 기록이 남지 않는다고 알린다.

### 13단계: 자동 테스트 (브랜치 `feature/tests`)

- JUnit 5 + AssertJ + Testcontainers(PostgreSQL). 단위 테스트(풀·지갑·정산·카탈로그·뉴스·업무·순찰·방·세력), 실제 콘텐츠 파일 검사, DB 테스트(회원·결과·명예의 전당), WebSocket으로 한 판 끝까지 하는 테스트. 52개, 약 15초.
- Boot 3.2의 Testcontainers 1.19는 Docker 29와 통신하지 못해 1.21.4로 올렸다.

### 14단계: 웹 음성 채팅 ([PR #15](https://github.com/2026-2-Artificial-Intelligence2/AI2-BE/pull/15), [PR #16](https://github.com/2026-2-Artificial-Intelligence2/AI2-BE/pull/16))

- WebRTC 메시 연결. 서버는 참여·음소거 상태를 `state.members`에 싣고 연결 정보(`VOICE SIGNAL` → `voiceSignal`)만 전달한다. 음성 데이터는 서버를 거치지 않는다.
- 플레이테스트: 같은 와이파이, **서로 다른 와이파이끼리**(2026-11-27 확인) 모두 실제 마이크로 목소리가 오갔다. 그러나 휴대폰을 데이터로 바꾸자 참여·소리 크기 막대는 정상인데 목소리만 오가지 않았다. 통신사 데이터망이 직접 연결을 막기 때문이다. `VOICE_ICE_SERVERS`로 TURN(중계)을 넣으면 음성 참여 때 `voiceConfig`로 내려주게 했다. TURN 계정은 비용이 생길 수 있어 마지막 배포 때 붙이기로 했다.

### 15단계: 요청 ID ([PR #17](https://github.com/2026-2-Artificial-Intelligence2/AI2-BE/pull/17))

- 서버가 연결 직후 `hello`를 보내고, `{"requestId","command"}` 요청에는 `ack`, 오류에는 `requestId`와 `command`를 붙인다. 화면이 오류를 엉뚱한 버튼 밑에 보여 주던 문제를 고쳤다. 텍스트 명령도 그대로 된다.

### 17단계: 오늘의 직원상 (AI2-BE PR #22, AI2-FE PR #15)

- 퇴근 `result`에 `awards`를 넣는다. 훈계(적발·업무 방치)를 가장 많이 받은 사람(`scolded`), 가장 많이 잃은 사람(`biggestLoss`), 업무를 가장 많이 한 사람(`hardestWorker`). 동점이면 함께 받고, 해당자가 없으면 그 상은 빠진다.
- 화면은 팀 판에서만 "오늘의 직원상" 칸을 보여 준다(부장님 단골상·눈물의 퇴근상·업무왕). 내가 받은 상은 금색으로 강조한다.
- 팀 1위 축하 문구를 "오늘의 퇴근왕!"에서 "오늘의 주식왕!"(동점 "공동 주식왕!")으로 바꿨다.

### 18단계: 부장님이 소리를 듣는다 (AI2-BE PR #23)

- 마이크 소리 50 이상(소리 막대 절반)이 1초 이어지면(말 사이 0.5초 이하 틈은 이어진 것으로) 부장님이 그 사람에게 걸어간다. 도착하면 평소처럼 화면을 본다.
- `MIC`가 올 때와 매초(같은 크기가 이어져 `MIC`가 다시 오지 않을 때) 잰다. 점심시간·훈계 중·연결 끊김·퇴근 뒤에는 판정하지 않는다.
- 화면 변경은 없다. 부장님이 다가오는 발소리로 알 수 있다.

### 19단계: 효과음 ([AI2-FE PR #16](https://github.com/2026-2-Artificial-Intelligence2/AI2-FE/pull/16))

- 효과음 실험실(저장소 밖 `office-stock/sound-lab`)에서 합성 소리 24개를 만들어 들어 보고, AI로 생성한 녹음 파일과 비교해 소리마다 더 나은 쪽을 골랐다.
- **녹음 파일**(`public/sounds`): 부장님 발소리, 헛기침(2종 무작위), 부장님 복귀(문), 적발, 결재 도장, 메신저, 빠따(2종 무작위), 직원상. 불러올 때 앞뒤 무음을 자르고(도장 파일은 앞에 0.87초 무음이 있었다), 모노로 바꾸고(방향 소리용), 크기를 맞춘다. 못 불러오면 합성 소리로 대신한다.
- **합성 소리**: 매수·매도 체결, 속보, 찌라시, 업무 완료·오답, 지정가 체결, 반대매매, 점심시간, 퇴근, 주식왕 팡파르, 손해 퇴근, 창 전환, 출근, 비상 대출, 버튼 클릭.
- 빠따 소리는 훈계 애니메이션의 타격 순간(0.95·2.05·3.2초)에 맞춘다. 정산 화면은 퇴근 종 → 팡파르(혼자 하기 손해면 실망음) → 직원상 공개 순서다.
- 재접속으로 다시 받은 메시지로는 소리가 나지 않는다(접속 뒤 첫 업무·시세는 기준으로만 삼는다).

### 20단계: 설정·배경음악·발소리 표시·사내 알림 ([AI2-BE PR #24](https://github.com/2026-2-Artificial-Intelligence2/AI2-BE/pull/24), [AI2-FE PR #17](https://github.com/2026-2-Artificial-Intelligence2/AI2-FE/pull/17))

- **설정 버튼:** 다크 모드 버튼 자리에 설정 창을 두고 화면 테마와 소리 크기를 모았다. 효과음과 부장님 소리를 따로 조절하도록 소리 갈래를 나눴고, 음성 채팅 음량은 사람별 음량에 곱한다. 음성 버튼은 자주 누르므로 따로 둔다.
- **발소리 앞뒤 구분:** 이어폰의 HRTF만으로는 앞뒤가 잘 구분되지 않아, 뒤에서 나는 소리일수록 높은 소리를 깎아 먹먹하게 들려준다(바로 뒤 1.3kHz, 앞 12kHz).
- **화면 발소리 표시:** 부장님이 내 뒤쪽(왼쪽 뒤·바로 뒤·오른쪽 뒤)으로 가까이 오면 컴퓨터 화면 아래에 방향과 거리(가까워요·바로 근처)를 띄운다. 앞과 옆은 눈으로 보이므로 띄우지 않는다. 발소리와 같은 정보만 주고 누구에게 가는지는 알리지 않는다.
- **사내 알림:** 팀 방에서 누가 훈계로 불려 가면 서버가 단체방에 이유와 함께 알린다(`chat`의 `system: true`). 일반 메시지처럼 번호가 붙어 안 읽은 수·미리보기·기록에 그대로 쓰인다.
- **배경음악:** Office.mp3(1시간·86MB)의 14:00~18:00을 잘라 AAC 96kbps(3.0MB)로 넣었다. 두 벌을 4초 크로스페이드로 이어 반복하고, 출근에 켜고 퇴근에 끈다. 부장님이 걷는 동안 40%로 줄인다. 기본 음량 80%.
- **메신저 M 키:** M으로 열고 M으로 닫는다. 입력 칸에 쓰던 글이 있으면 글자로 들어간다.
- **아이콘:** 이모지·기호 아이콘을 Font Awesome Free(Solid)로 바꿨다. 주가 등락 ▲▼는 국내 증시 표기 관례라 그대로 둔다.

## 3. 주요 결정과 근거


| 주제 | 결정 | 근거 |
|---|---|---|
| 순찰 유예 | 부장님이 도착한 뒤 2초 기다렸다가 점검한다(유지). | 집중하면 피할 수 있고, 집중하지 않으면 걸리는 것이 의도다. |
| 가격 모델과 LLM | 시세 계산에는 LLM을 쓰지 않는다. 뉴스 문구가 필요하면 미리 생성해 파일로 쓴다. | 비용, 지연, 재현성, 공정성 때문이다. 미리 만들어 두면 판당 비용이 0원이다. |
| 시세 갱신 | 1초 | 더 실감 난다. 비율을 초 단위로 정의해 흔들림 세기는 그대로 뒀다. |
| 풀 깊이 | 종목당 1,000주 | 100주에서는 뉴스를 잘 읽어도 판당 약 2천 원밖에 못 번다. 1,000주에서는 뉴스 매매가 판당 약 2만~2.7만 원이고, 무작위 매매는 손해다. |
| 퇴근 평가 | 기준가가 아니라 청산가(혼자 전부 팔 때 받을 금액)로 평가한다. | 기준가로 평가하면 끝나기 직전 대량 매수만으로 순자산이 오른다(60주에 +8,796원). |
| 종목 코드 | 고정 영문 코드와 표시 이름을 나눴다. | 이름에 띄어쓰기를 쓸 수 있고, 프론트엔드도 안정적인 키로 쓸 수 있다. |
| 여러 종목 뉴스 | 종목별 변화율을 적고, 발표 때마다 ±25%로 흔든다. | 같은 뉴스라도 종목마다, 판마다 반응이 다르게 하려는 것이다. |

| 배경음악 위치 | 프론트엔드 정적 파일(4분 반복) | 화면에서만 쓰는 자원이고, 한 번 받으면 브라우저가 저장한다. 서버 스트리밍은 1시간 원본을 쓸 수 있지만 저장소·배포·데이터 사용량 부담이 크다. |

| 점심시간 | 근무 시간의 40% 지점부터 10% 동안이고, 20% 확률로 20초 일찍 복귀한다. | 판에 강약을 주고, 방심을 노리는 장치다. |

## 4. 검증 방법과 결과

자동 테스트는 `./gradlew test`로 돈다(57개, Docker 필요, README "테스트"). 그 전까지와 테스트로 옮기기 어려운 것은 아래 방법으로 확인했다.

- **봇:** Node.js WebSocket 봇 2~3명이 실제 서버에 붙어 명령을 보내고, 응답과 숫자를 확인했다. 재접속, 대출, 지정가, 메신저처럼 규칙이 까다로운 기능은 실패 경우(잘못된 열쇠, 한도 초과, 다른 창 접속 등)도 확인했다.
- **브라우저:** 임시 화면과 프론트엔드(AI2-FE) 개발 서버로 직접 조작했다. 팝업, 차트, 호가창, 확대·축소·끌기, 좁은 창 배치, 회원가입·게스트·1인 플레이·명예의 전당, 데스크톱(1280px)·휴대폰(375px) 화면을 확인했다. 음성은 마이크 대신 합성음을 넣은 탭 두 개로 양방향 연결·음소거·음량을 확인했다.
- **시뮬레이션:** 시장·순찰 코드를 그대로 불러 수백 판을 돌려 수치를 정했다.

| 시뮬레이션 | 결과 |
|---|---|
| 가격 변동(500판) | 호재 속보에 30주 매매하면 판당 약 +2.7만 원, 무작위 매매는 손해였다. |
| 의심 게이지(400판) | 40초 간격으로 업무하면 헛기침·훈계가 0번이었다. 50초 간격이면 헛기침 7.1회, 훈계 3.0회였다. |
| 여러 종목 뉴스(300회) | 평균 반응이 적힌 값과 같았다(+7% → +6.6%). |
| 대출 몰빵(600판) | 성실(평균 137,280원) > 몰빵(대출 0원 108,189원 … 10만 원 4,531원) |
| 대출 펌핑 | 혼자서는 이득이 없었다. 바로 되팔면 손익이 정확히 이자만큼 손해였다. |

## 5. 아직 확인하지 못한 것과 알려진 한계

**확인하지 못한 것**
- 업무 수당(35,000원)은 아직 실제 업무 시간 기록으로 맞추지 않은 값이다.
- Docker 이미지 빌드와 클라우드 배포(서버 + PostgreSQL). 지금은 DB만 Docker로 띄운다.
- 휴대폰 데이터망에서 TURN을 거친 음성(TURN 계정이 아직 없음). 학교·회사 와이파이처럼 막힌 네트워크.
- 회원 기능의 실제 사용(여러 기기 로그인, 비밀번호 분실 시 대처 방법이 없음).
- 실제 판에서 일찍 돌아온 부장님에게 적발되는 장면과 메신저 창 적발 장면. 판정 로직만 따로 확인했다.
- 헛기침 소리가 실제로 어떻게 들리는지.
- 효과음 가운데 매도·지정가·반대매매·대출·오답·적발·빠따는 실제 판에서 나는 것을 보지 않았다(코드만 연결). 효과음끼리의 크기 균형, 문 소리 길이(약 4.6초).
- 클라우드 배포

**알려진 한계**
- 방이 서버 메모리에만 있어서, 서버를 다시 켜면 진행 중인 방이 사라진다. 서버는 한 대만 띄워야 한다.
- 호가가 얇은 편이다(판돈을 키운 뒤에도 풀 깊이는 시작 자금의 10배로 같다). 한 칸(0.5%)에 시작 자금의 약 0.5%어치라서 수십 주만 사도 여러 칸이 움직인다.
- 매매 충격의 70%가 남으므로, 누군가 크게 사면 그 종목을 들고 있던 다른 사람의 평가액이 오른다(띄운 사람이 비싸게 산 값이다). 신용 매수로 쓸 수 있는 돈이 커져 이 효과도 커질 수 있다. 예전 메모: 큰 금액으로 펌핑하면, 그 종목을 들고 있던 다른 사람이 이득을 볼 수 있다(대출 상한으로 1.44배 정도에 묶었다).
- 발소리 위치가 구간 끝에서 살짝 튄다.
- 분봉 같은 다른 봉 단위가 없다.

## 6. 다음에 할 일

**완료:** 설정 버튼과 소리 크기, 배경음악, 화면 발소리 표시, 사내 알림, 효과음, 오늘의 직원상, 부장님이 소리를 듣기, 첫·2차 플레이테스트 반영, 뉴스·종목 늘리기, 판마다 상장 종목, 회원·게스트, 1인 플레이와 명예의 전당, 음성 채팅(TURN은 배포 때), 자동 테스트 1차, 프론트엔드 입장 화면, 3D 사무실(Meshy 캐릭터·소품·시간대 조명), 정산 화면(주식왕·손익 색), 방장 나가기.

1. **3차 플레이테스트:** 1인 플레이(세력)와 명예의 전당이 실제로 재밌는지 확인한다. (음성은 같은 와이파이·서로 다른 와이파이에서 확인 완료, 데이터망은 TURN을 붙인 뒤 다시 확인)
2. **배포 준비:** 서버와 PostgreSQL을 함께 띄우는 구성(compose에 서버 추가 또는 관리형 DB), 클라우드 배포, TURN 계정 연결(`VOICE_ICE_SERVERS`).
3. **재미 요소:** 대기실·정산 화면 음악, 근무 중 사무실 배경 소리(에어컨·타자). 상한가·하한가는 하지 않기로 했다.
4. **회원 마무리:** 내 전적 보기, 회원 탈퇴, 비밀번호 분실 대책, 꾸미기 항목 정하기와 화면(서버는 저장만 준비됨), 프론트엔드의 이름·비밀번호 바꾸기 화면.
5. **테스트 보강:** 지정가 체결, 반대매매, 재접속, 점심 일찍 복귀, 방장이 게임 중에 나갈 때 대기실로 돌아가기.
6. **그 밖:** 발소리 끊김·구간 끝에서 튀는 버그 수정, 분봉 검토, 새 20종목 뉴스 보강(종목당 20장 이상), 3단계(LLM 부장님, 고자질, 웃음 감지).
