# 진행 기록

"부장님 몰래" 백엔드를 어떤 순서로, 어떤 결정을 거쳐 만들었는지 정리한 문서다. 정리 시점은 2026-11-26, PR #4 머지(`32ecf81`) 직후다.

- 지금의 규칙과 수치는 [GAME_DESIGN.md](../GAME_DESIGN.md)가 기준이다.
- 서버와 주고받는 명령·메시지는 [PROTOCOL.md](../PROTOCOL.md)에 있다.
- 실행과 배포 방법은 [README.md](../README.md)에 있다.

이 문서는 그 결과에 이르기까지의 과정을 담는다.

## 1. 지금 할 수 있는 것

친구 2~4명이 초대 코드로 한 방에 모여, 방장이 정한 근무 시간(기본 15분) 동안 한 판을 끝까지 할 수 있다. 1단계 규칙은 웹 음성 채팅을 빼고 모두 들어갔다. 음성 채팅은 구현 항목으로 정해 두었고(GAME_DESIGN.md "웹 음성 채팅"), 그 전까지는 디스코드로 대신한다.

| 영역 | 내용 |
|---|---|
| 방 | 초대 코드 입장, 방장 시작, 근무 시간 선택(5·10·15·20분), 재접속, 방 나가기, 같은 방에서 다시 하기 |
| 업무 | 엑셀 집계·전자결재·메일 분류를 섞은 업무 창, 수당, 업무 시간 플레이테스트 기록(CSV) |
| 시장 | 일반 종목 28개(실제 기업 이름 패러디 20개 포함) 중 판마다 12개 무작위 상장, 레버리지·인버스 종목 2개(목록 파일로 추가), 뉴스 270장(실제 사건 모티브 포함, 25~40초 무작위 간격), 1초 갱신 가격 변동, 조작 방지 보정(충격 영구화·속보 갭·거래 비용), 속보·찌라시, 여러 종목 뉴스, 뉴스 본문 |
| 주문 | 딸깍 매매(시세표 버튼, 수량·비율·전량), 수량·금액 시장가 주문, 신용 매수(2·3·5배, 반대매매), 지정가 주문(개수 제한 없음, 안 보고 있어도 체결), 주문 전 예상 금액, 평균 매수가·손익·담보 비율, 내 거래 내역 |
| 차트 | 호가창(풀 공식), 10초 봉, 거래량, 뉴스 표시, 출근 전 30분 주가 흐름, 확대·축소·이동 |
| 부장님 | 방향성 발소리 순찰(20~38초 간격), 주식·메신저 창 적발 훈계, 의심 게이지(업무 방치, 나에게만 보임), 마이크 소리 크기 공유, 헛기침, 점심시간과 일찍 복귀 |
| 그 밖의 규칙 | 판돈 1천만 원, 비상 대출(누구나 한 판에 한 번, 최대 1천만 원, 이자 20%), 사내 메신저(단체방·귓속말·익명 찌라시) |
| 정산 | 퇴근 때 청산가로 평가한 순위표, 전체 매매 기록, 익명 찌라시 주인 공개 |
| 연동·배포 | 허용 주소 설정(따로 만든 프론트엔드 연결), 통신 규약 문서, 실행 파일, Dockerfile, 터널·클라우드 안내 |

서버 코드는 자바 약 2,500줄, 확인용 임시 화면(`index.html`)은 약 1,100줄이다.

## 2. 진행 순서

### 0단계: 기존 코드 검토 (레포 이전)

이미 동작하던 것을 봇 2명과 브라우저로 한 판 돌려 확인했다.

- **이미 동작하던 것:** 방 만들기·입장·시작, 합계 업무와 수당, 종목 3개 상수곱 풀 매매, 뉴스 21장, 2초 순찰과 방향성 발소리, 주식 창 적발과 10초 훈계, 뉴스 알림창.
- **검토에서 나온 개선점:**
  - 화면의 기준가와 실제 체결가가 달라 헷갈린다.
  - 가격이 뉴스 사이에 거의 멈춰 있다.
  - 도착 뒤 2초 유예가 넉넉하다.
  - 발소리 위치가 구간 끝에서 살짝 튄다.

### 1단계: 첫 커밋 전 작업 (`0b4cdfe`)

레포를 만들기 전에 원래 폴더에서 한 작업으로, 첫 커밋에 함께 들어갔다.

- **주문 전 예상 체결 금액:** 서버와 같은 공식으로 화면에서 계산한다.
- **가격 변동 모델:** 평소 흔들림, 뉴스 반응 다양화(과잉 반응, 소문에 사서 뉴스에 판다), 찌라시(진짜 70%, 가짜 30%), 매매 흔적, 장 마감 변동성을 넣었다. 500판 시뮬레이션으로 수치를 정했다.
- **풀 깊이:** 100주에서 1,000주로 늘렸다. 100주에서는 뉴스를 잘 읽어도 판당 2천 원 남짓밖에 못 벌었다.
- **시세 갱신:** 2초에서 1초로 바꿨다. 모든 비율을 초 단위로 바꿔서 체감은 그대로이고, 순찰은 2초 박자를 유지한다.
- **업무 시간 기록:** 업무 1건마다 전체 시간과 업무 창 기준 시간을 CSV로 남긴다. 업무 수당을 정할 근거로 쓴다.
- **레포 정리:** 폴더를 `office-stock/office-stock-BE`로 옮기고 GitHub 레포(AI2-BE)를 만들었다.

### 7단계: 종목과 뉴스 늘리기 (브랜치 `feature/more-stocks-news`)

- 종목 5개(하늘항공·온누리제약·반짝반도체·든든은행·배달번개)를 출근 전 흐름과 함께 더했다.
- 뉴스를 126장으로 늘렸다. 여러 종목·외부 사건 뉴스 46장에는 전염병 대유행, 금리, 유가, 반도체 부족 같은 실제 사건 모티브가 들어 있다.
- 뉴스 간격을 20초 고정에서 25~40초 무작위로 바꿨다. 플레이테스트에서 뉴스가 너무 잦다는 의견이 있었다.
- 200판 시뮬레이션: 20분 판에 속보 평균 36.5번, 찌라시 22.1번, 한 판 안 반복 0번.
- 이어서 실제 기업 이름을 다른 업종과 섞은 패러디 종목 20개(삼성자동차, 현대전자, 카카오조선, 롯데반도체 등)를 더했다. 일반 종목은 28개, 뉴스는 270장(여러 종목 뉴스 70장)이 됐다. 사드 보복, 일본 수출 규제, 레고랜드, 동학개미, 수에즈 운하, 후쿠시마, 누리호 같은 사건을 모티브로 한 외부 뉴스를 더했고, 기존 외부 뉴스에도 새 종목의 반응을 넣었다.

### 8단계: 판마다 상장 종목 (브랜치 `feature/listed-stocks`)

- 30종목일 때 시세 메시지를 재 보니 매초 15.4KB(그중 호가 10.6KB), 시작 차트 452KB였다. 프론트엔드는 호가·풀을 선택한 종목 것만 쓰고, 봉은 모든 종목을 이어 붙인다.
- 판마다 일반 종목 12개를 무작위로 상장하고(`game.stocks-per-game`), 뉴스 덱과 `catalog` 메시지를 그 판 종목에 맞췄다. 기초 종목이 뽑히면 레버리지 종목도 함께 나온다.
- 결과: 매초 6.5KB, 시작 차트 181KB. 종목 하나가 한 판에 받는 속보는 평균 1.3번 → 4.6번.
- 프로토콜 모양은 그대로라 프론트엔드는 바꿀 것이 없다. 다만 종목 목록을 고정해 두지 말고 매 판 `catalog`로 받아야 한다.

### 9단계: 2차 플레이 피드백 (브랜치 `feature/easier-tasks`)

- 엑셀 집계를 쉽게 했다. 거래처 3~5개·세 자리 금액에서 2~3개·100 단위 금액(예: 700+900)으로 바꿨다. 전자결재는 그대로 둔다(어렵지 않다는 의견).
- 업무 게이지를 남이 아니라 **나에게** 보이게 바꿨다. 내 주식을 보느라 남의 게이지를 볼 틈이 없었다. 동료에 대해서는 훈계 중인지만 보낸다.
- 마이크 소리 크기를 나와 다른 사람 모두 볼 수 있게 했다(`MIC n`, `mic` 메시지, `market.micLevels`). 목소리는 보내지 않고 크기만 보낸다.

## 3. 주요 결정과 근거

| 주제 | 결정 | 근거 |
|---|---|---|
| 순찰 유예 | 부장님이 도착한 뒤 2초 기다렸다가 점검한다(유지). | 집중하면 피할 수 있고, 집중하지 않으면 걸리는 것이 의도다. |
| 가격 모델과 LLM | 시세 계산에는 LLM을 쓰지 않는다. 뉴스 문구가 필요하면 미리 생성해 파일로 쓴다. | 비용, 지연, 재현성, 공정성 때문이다. 미리 만들어 두면 판당 비용이 0원이다. |
| 시세 갱신 | 1초 | 더 실감 난다. 비율을 초 단위로 정의해 흔들림 세기는 그대로 뒀다. |
| 풀 깊이 | 종목당 1,000주 | 100주에서는 뉴스를 잘 읽어도 판당 약 2천 원밖에 못 번다. 1,000주에서는 뉴스 매매가 판당 약 2만~2.7만 원이고, 무작위 매매는 손해다. |
| 퇴근 평가 | 기준가가 아니라 청산가(혼자 전부 팔 때 받을 금액)로 평가한다. | 기준가로 평가하면 끝나기 직전 대량 매수만으로 순자산이 오른다(60주에 +8,796원). |
| 종목 코드 | 고정 영문 코드와 표시 이름을 나눴다. | 이름에 띄어쓰기를 쓸 수 있고, 프론트엔드도 안정적인 키로 쓸 수 있다. |
| 여러 종목 뉴스 | 종목별 변화율을 적고, 발표 때마다 ±25%로 흔든다. | 같은 뉴스라도 종목마다, 판마다 반응이 다르게 하려는 것이다. |
| 패러디 종목 이름 | 실제 기업 이름을 다른 업종과 섞는다(삼성자동차, 현대전자 등). | 친구들끼리 알아보기 쉽고 웃기다. 실제 회사와 관계없는 지어낸 뉴스라는 점을 문서에 밝혀 둔다. 일반 공개 배포 때는 상표 문제를 다시 검토한다. |
| 판마다 상장 종목 | 28개 중 12개를 무작위로(업종 무관), 기초 종목이 뽑힌 레버리지는 함께 | 종목이 많으면 뉴스가 흩어져 종목당 속보가 판당 1~4번뿐이었다. 12개면 평균 4.6번이고 판마다 시장이 달라진다. 시세 메시지도 절반 이하로 준다. |
| 업무 게이지 공개 범위 | 내 것만 나에게(처음에는 남에게만) | 플레이해 보니 남의 게이지를 볼 틈이 없었다. 내 게이지를 보고 업무 타이밍을 스스로 잡는 편이 낫다. |
| 업무 난이도 | 엑셀 합계는 100 단위 두세 개만 | 주식과 부장님에게 쫓기는 상황에서 세 자리 수 여러 개를 더하는 것은 너무 어려웠다. |
| 뉴스 덱 크기와 간격 | 최대 판(20분)의 약 3배인 126장, 25~40초 무작위 간격 | 판마다 다른 조합이 나오고 한 판 안에서는 반복되지 않는다. 간격을 흔들어 다음 뉴스 시각을 외울 수 없게 한다. |

## 4. 검증 방법과 결과

자동 테스트는 아직 없다. 기능마다 아래 방법으로 확인했다.

- **봇:** Node.js WebSocket 봇 2~3명이 실제 서버에 붙어 명령을 보내고, 응답과 숫자를 확인했다. 재접속, 대출, 지정가, 메신저처럼 규칙이 까다로운 기능은 실패 경우(잘못된 열쇠, 한도 초과, 다른 창 접속 등)도 확인했다.
- **브라우저:** 임시 화면으로 직접 조작했다. 팝업, 차트, 호가창, 확대·축소·끌기, 좁은 창 배치를 확인했다.
- **시뮬레이션:** 시장·순찰 코드를 그대로 불러 수백 판을 돌려 수치를 정했다.

| 시뮬레이션 | 결과 |
|---|---|
| 가격 변동(500판) | 호재 속보에 30주 매매하면 판당 약 +2.7만 원, 무작위 매매는 손해였다. |
| 의심 게이지(400판) | 40초 간격으로 업무하면 헛기침·훈계가 0번이었다. 50초 간격이면 헛기침 7.1회, 훈계 3.0회였다. |
| 여러 종목 뉴스(300회) | 평균 반응이 적힌 값과 같았다(+7% → +6.6%). |
| 대출 몰빵(600판) | 성실(평균 137,280원) > 몰빵(대출 0원 108,189원 … 10만 원 4,531원) |
| 대출 펌핑 | 혼자서는 이득이 없었다. 바로 되팔면 손익이 정확히 이자만큼 손해였다. |

## 5. 아직 확인하지 못한 것과 알려진 한계

**확인하지 못한 것**
- 실제 사람끼리의 플레이테스트. 업무 1건 시간을 아직 몰라서 업무 수당(350원)은 임시값이다.
- Docker 이미지 빌드. 작업한 컴퓨터에서 Docker 데몬이 꺼져 있었다.
- 실제 판에서 일찍 돌아온 부장님에게 적발되는 장면과 메신저 창 적발 장면. 판정 로직만 따로 확인했다.
- 헛기침 소리가 실제로 어떻게 들리는지.
- 터널(cloudflared, ngrok)과 클라우드 배포

**알려진 한계**
- 방이 서버 메모리에만 있어서, 서버를 다시 켜면 진행 중인 방이 사라진다. 서버는 한 대만 띄워야 한다.
- 호가가 얇은 편이다(판돈을 키운 뒤에도 풀 깊이는 시작 자금의 10배로 같다). 한 칸(0.5%)에 시작 자금의 약 0.5%어치라서 수십 주만 사도 여러 칸이 움직인다.
- 매매 충격의 70%가 남으므로, 누군가 크게 사면 그 종목을 들고 있던 다른 사람의 평가액이 오른다(띄운 사람이 비싸게 산 값이다). 신용 매수로 쓸 수 있는 돈이 커져 이 효과도 커질 수 있다. 예전 메모: 큰 금액으로 펌핑하면, 그 종목을 들고 있던 다른 사람이 이득을 볼 수 있다(대출 상한으로 1.44배 정도에 묶었다).
- 발소리 위치가 구간 끝에서 살짝 튄다.
- 분봉 같은 다른 봉 단위가 없다.
